# 麦克风断流问题排查记录

> 板子：正点原子 DNESP32S3B（ESP32S3 BOX，V1.0 硬件参考手册对应版本）
> 问题：麦克风正常工作 **45–70 秒**后，ADC 停止输出数据（全 0），只有整机重启能恢复
> 状态：**✅ 已解决**。根因是**麦克风 PGA 增益开到 42dB（上限），ADC/ALC 过载后进入保护状态**
> 日期：2026-11-26

---

## 0. 结论（先看这里）

```c
// ❌ 错误：42dB 是 ES8311 PGA 的最大增益，长期工作会过载
s_codec->set_mic_gain(s_codec, 42.0f);

// ✅ 正确：24dB，实测连续工作 3 分钟无断流，唤醒和 ASR 均正常
s_codec->set_mic_gain(s_codec, 24.0f);
```

**为什么只有重启能恢复**：过载触发的是 ADC 模拟前端的保护状态，不改变寄存器、
不影响 I2C/I2S，只有走完整的 codec 上电初始化（`open()` 内部会重新给 ADC 上电）才能解除。
这解释了本记录里"重放寄存器/重建 I2S/换电源全部无效、只有重启有效"的所有现象。

**线索来源**：正点原子例程用的是 `es8311_set_mic_gain(7)`（较低的增益档），
且代码里原本就有一行注释「实测 30dB 合适」——是历史调试遗留，后来被改成 42dB 一直没察觉。

**验证数据**：

| 增益 | 观察时长 | 断流次数 | 电平（均值） |
|---|---|---|---|
| 42dB | 反复测试 | 20~70 秒必断 | 700~1000 |
| **24dB** | **180+ 秒** | **0 次** | 83~254（说话时峰值 7000~10000，足够唤醒） |

## 1. 现象（问题时期的记录）

| 项目 | 表现 |
|---|---|
| 首次断流时间 | 开机后 45–70 秒（两块板分别约 48s / 66s） |
| 断流方式 | **硬切**：前一秒均值 698 → 0.25 秒均值 251 → 完全为 0 |
| 断流后 I2C | 正常，ES8311 寄存器可读可写，值与初始化时**逐个比对完全一致** |
| 断流后 I2S | 读取无超时（`i2s_channel_read` 一直成功），但**数据全 0** |
| 断流后 codec 寄存器 | 0x00=0x80、0x0E=0x02，与正常时相同 |
| 恢复手段 | **只有 `esp_restart()` 有效**，且重启后立即恢复 |
| 复现性 | **两块同型号板子均可复现**，表现一致 |

## 2. 已验证并排除的方向

| # | 假设 | 实验方法 | 结果 |
|---|---|---|---|
| 1 | codec 寄存器被改写 | 影子层记录全部写入，逐寄存器读回比对 | ✅ 全部一致，非寄存器问题 |
| 2 | 芯片被复位 | 检测 0x0E 是否变成上电默认 0x7F | ❌ 未发生（早期看到的 0x7F 是 close/open 造成的假象） |
| 3 | 重放顺序错误 | 按**原始写入顺序**重放 104 个寄存器 | ❌ 全部写成功，麦克风不恢复 |
| 4 | 写入速度太快 | 每寄存器间隔 **3ms** 慢速重放 | ❌ 无效 |
| 5 | I2C 总线故障 | 每秒读寄存器 + 统计失败 | ❌ 一直成功 |
| 6 | 时钟需要重锁 | 停 BCLK/WS **1.5 秒**再启 | ❌ 无效 |
| 7 | I2S 外设卡死 | `i2s_del_channel` + `i2s_new_channel` **整体重建** | ❌ 无效 |
| 8 | TX DMA 空转导致主时钟停摆 | 每 100ms 往 TX 喂静音保活 | ❌ 无效 |
| 9 | 供电不足 | 换 5V/2A 外部电源（USB_SLAVE 口单独供电） | ❌ 断流依旧（首次断流时间从 ~50s 变 106s，属波动） |

| 11 | 动态调频（DFS）导致时钟分频错误 | 检查 `CONFIG_PM_ENABLE` | ❌ 未启用 |
| 12 | 个体硬件故障 | 换第二块同型号板实测 | ❌ **两块表现一致** |

## 3. 当时的结论（**已被推翻，保留作为排查思路参考**）

**当时判断：这是板子音频模拟部分的硬件缺陷，固件层面无法修复。**

判断依据：

1. **两块板表现完全一致** → 排除个体不良品
2. **断流是硬切** → 排除热漂移、供电缓降（这两类都是渐变）
3. **所有数字接口全程正常** → 只有模拟/ADC 侧停止工作
4. **所有软件恢复手段失效、只有重启有效** → 存在一个只能通过 codec 完整上电初始化才能复位的状态

当时推测是「咪头偏置电路 / ADC 模拟前端存在自动关断机制」——**方向对了，但原因不是偏置电路，而是 PGA 增益过载**。

> 注：重启并**不会**给 codec 断电（3.3V 一直存在），所以真正被复位的是 codec 内部的模拟上电状态机——
> 这也是为什么"重写寄存器"无效、"重新上电初始化"有效。

---

## 4. 对自研硬件的设计建议

1. **给音频 codec 单独可控的复位脚**（接 ESP32 GPIO），固件可以只复位 codec，不用重启整机
2. **给麦克风偏置电路独立供电或可控使能**，并加足够大的去耦电容
3. **选用带 AEC 参考回路的 codec**（如 ES7210/ES8311 组合），方便后续做"边放边听"
4. 尽量选**有完整中文手册 + 官方 ESP-IDF 例程**的 codec，方便对比验证
5. 硬件设计时预留**音频电流测试点**，方便定位是 codec 还是功放的问题

---

## 5. 问题时期的临时对策（已被第 0 节的修复取代）

断流检测 → 重放一次配置 → 失败 2 次后 **自动重启整机**（死机窗口约 6 秒）。

相关代码全部在 `main/wake_word.cpp`：

- `ShadowCtrl` / `codec_replay_regs()`：寄存器影子层，记录并重放初始化序列
- `codec_diff_regs()`：逐寄存器比对（诊断用，已降频到 10 秒一次）
- 断流判定用**均值**（`mean > 50`）而不是峰值，避免重放产生的 32768 瞬态被误判成"已恢复"
